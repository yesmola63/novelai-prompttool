# NovelAIPromptTool

> 这个项目始于一个很实际的问题：长期使用 NovelAI 之后，提示词一直存在手机笔记软件里，翻找和阅读都不方便；改用 Word 文档，又得为每条提示词手动分类、整理图片，手机上依然不好看。于是就有了这个软件的雏形。

## 网页版：NovelAI 提示词记录

### 基础信息

- 类型：`网页`
- 网址：`https://novelai-common.arisuhhome.xyz`（已停运）
- 版本：`—`（那时还没有版本的概念）

这是一个部署在 **Cloudflare** 上的纯静态网页。为什么是静态？因为我没有资金去购买服务器。这也导致**网页体验极差**，~~有些访客要等半天，几张图片每张还只加载出一半~~。整体样式风格与现在差不多。

在做网页之前，保存提示词的文件经历了一连串转换：先是从笔记导出的 **SQLite 数据库**，再用 Python 转成 **txt**，最后又用 Python 转成 **Word 文档**。但那份文件只有提示词和图片，没有任何分组，查找很困难。于是我请拥有**虚拟电脑环境**的豆包，按照我提供的角色对照表给所有提示词分组、标注角色——不过部分角色被强行翻译了，比如 kipfel 被译成“普基费尔”。之后用 Word 保存了一段时间，但正如前面所说，手机上实在不好用。于是我想到了网页界面的高自定义性，第一版就这样诞生了。

### 第一版

仍然借助豆包，把转换过程中产生的 txt 转成 **JSON**，然后写了网页。当时的网页只能查看已有提示词，不能添加也不能删除，纯粹是观赏用的。

### 第二版

因为我一直在产出新的 NovelAI 提示词，而网页不能添加，于是我和大名鼎鼎的 **DeepSeek** 一合计，研究出一种方法：使用 **Cloudflare 的 KV 存储**，添加提示词的功能就有了。当时能填写的内容和现在差不多，只是图片只能填链接，所以那段时间一直用图床保存图片，再把链接填进来。

### 第三版

因为“普基费尔”的翻译问题需要修改，但这是静态网页，不好改；而且这也不是 KV 存储能解决的，因为那部分是固定数据。于是我退而求其次：先把静态内容改正，之后新增的提示词因为存在可读写的 KV 存储里，就顺势加上了编辑和删除按钮。

### 第四版（并未正式上线）

保存图片需要第三方图床，上传很麻烦；而且图床有的访问慢，有的限制数量或大小，导致图片分散在很多个图床里（至今没清理干净，~~索性不清理了~~）。于是又是 **DeepSeek** 建议，我用上了当时买域名时阿里云的 **B2 存储桶**（详细过程就不展开了）。结果最后 B2 存储桶先欠费了，项目也就停了。

**随后网站长期静止。**

~~还是 Word 文档好用~~

## 电脑版：NovelAI 提示词记录

### 基础信息

- 类型：`网页前端 + Python 后端`

……好像没什么值得多说的，**总之与现在差不多**，只是当时没有版本的概念。

### 网页前端 + Python 后端的开端

因为图片难以管理、访问又极慢，网页版停机：所有部署过的静态网页（包括 KV 存储）都被保存到本地，部署网址全部删除。

之后为了更好的管理，我决定改用“更好的网页前端 + Python 后端”。也正是在这时，原本只有两个文件（`index.html`、`script.js`）的网页被拆分成许多文件，变成了模块化设计。不过当时只是自己用，所以**没有版本、没有打包提示词**，也没打算更新；其余功能与网页版一致，只是图片终于不再依赖图床了（~~太好了~~）。后来用 PyInstaller 打包成了 exe 程序。

### 手机软件的由来

做好电脑版之后，我开始分享这个软件。有些人用的是台式机——我用笔记本觉得方便，但用台式机的人就不太方便了；哪怕用笔记本，总不能为了看一眼提示词就把电脑打开吧？所以我想直接把电脑版转换成手机 APK。

于是我先是试了 **Buildozer**，为此装了 WSL，一通折腾后确实生成了一个 APK，但无法正常运行；接着又试了 GitHub 开源的 **WebToApp**，仍然不行，打开就提示“Python 服务器启动失败”。~~然后就这样放了一个月，因为放暑假了~~

## 手机版：NovelAI 提示词记录（NovelAIPromptTool）

### 基础信息

- 类型：`手机软件`
- 构建方法：`IntelliJ IDEA + Android SDK`
- 包名：`com.novelai.prompttool`
- 网页加载方式：`内置 NanoHTTPD 本地服务器`
- 语言：`Kotlin`

### 为何而来

其实那时我已经放弃了。直到 DeepSeek Harness 发布，加上我搞明白了怎么用 IntelliJ IDEA 构建 APK（还有很多其他因素就不一一列举了），我开始借助 DeepSeek 做一些事，发现还挺好用。于是让它把电脑版程序改造成可构建的 **Android Studio** 项目，并成功构建出可用的 APK——这才有了现在 NovelAI 提示词记录的安卓手机 + Windows 电脑双端。

为什么没有 iPhone 版？~~因为我自己用不上 iPhone~~（也确实如此：我没法测试，也不太清楚 iPhone 程序是什么形式）。
